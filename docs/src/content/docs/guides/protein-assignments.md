---
title: Manual protein assignments
description: Bind protein sequences to 3D spectra and confirm manual peak assignments.
---

1. Choose **Data → Import protein sequence** and open a FASTA file. Each record becomes a chain in one molecule. Check the molecule name, chain names and starting numbers before importing. The project stores the sequence and no longer needs the source file.
2. Select a 3D spectrum and open **Analyze → Protein assignments**. Select the molecule and bind the active spectrum. Repeat for each spectrum that uses the same molecule.
3. Pick or select a peak in the 3D peak table. In **Assignments**, choose **New candidate**. For each acquisition axis (F1, F2, F3), choose a residue and one atom or a set of atoms of the same element. An axis can stay unassigned. Save each alternative interpretation as a separate candidate.
4. Use **Confirm** to accept one candidate. A partial confirmation leaves its other axes unassigned. For a group, choose **One of these atoms (identity unresolved)** or **All members share this resonance** before confirming. **Unspecified (candidate only)** can be saved as a draft interpretation but cannot be confirmed. A shared resonance does not assert chemical equivalence or stereospecific assignment. Plotium checks atom names against the local [wwPDB Chemical Component Dictionary](https://www.wwpdb.org/data/ccd) catalog and needs a known nucleus on each assigned axis to confirm.
5. Expand **Sequence and associated peaks**, select a residue and click a result to switch spectra and locate its peak. Both candidates and confirmed results appear here.

The editor lists atoms compatible with the axis nucleus and their position in a standard linear peptide chain. `H2` is limited to the first residue, `OXT`/`HXT` to the last, and proline `H` to the first residue. These checks use sequence position, not displayed residue numbering. They apply to automation and project validation too. The catalog does not infer terminal protonation, capping, disulfides or other modifications. **Confirmed** means manually accepted, not automatic validation of chemistry or experiment connectivity.

Editing the targets or group meaning of a confirmed candidate withdraws confirmation. Editing its note, moving a peak, changing planes or phase, and renumbering a chain preserve confirmation. Delete a peak to remove its assignments with it; Undo restores both. Clear a spectrum's assignments before changing its binding. Clearing opens a review with the spectrum name and the affected peak, candidate and confirmation counts; confirm or cancel it. The review keeps its original spectrum even if you select another spectrum. If the project changes, review the updated counts before confirming. Unbind all spectra before deleting a molecule.

Save the project to keep the sequence, bindings and assignments. Under **Molecule details**, **Export JSON** includes the candidates and confirmation state alongside the measured coordinates, signed heights, nuclei and processing provenance. Select **Export only confirmed assignments** to omit other candidates. The report keeps each observation separate.

The panel scrolls when its contents exceed the available height; scroll down to reach **Save candidate**. **Active spectrum** names the spectrum and **Bound molecule** identifies its binding. The sequence browser can show another molecule; the candidate editor separately names its own spectrum and molecule. An open draft keeps its original target when you select another peak or spectrum.

Automation uses the document target. The CLI accepts FASTA text in a `protein.edit` import request via `plotium-cli tool run`. Use `protein.assignments.edit` with a dataset and peak ID, `protein.inspect` for lookup, and `protein.assignments.export` for a report. MCP clients use `plotium_plan` and `plotium_execute` for edits, or call `plotium_protein_inspect` and `plotium_protein_assignments_export` for reads.

Inspection defaults to compact molecule summaries, bindings, and associated peaks. To read a sequence, request `view: "chains"` with a molecule ID, then `view: "residues"` with the molecule and chain IDs. Residue rows contain the stable ID, one-letter code, and displayed number. Use `limit` and follow `next_offset` until it is null. The JSON export includes the full sequence.

Each atom target has `residue`, `members`, and `group_meaning`. The latter is `unspecified` by default; use `one_of` for one unidentified member or `shared` when all members share the observed resonance. Single atoms use `unspecified`. Changing this value withdraws confirmation just like changing the atoms. JSON exports include this value and an `assignment_semantics` explanation; observations are never automatically merged or averaged. For example, an alanine methyl resonance can use `members: ["HB1", "HB2", "HB3"]` with `group_meaning: "shared"`.

## Scientific context and initial structure scope

Expand **Scientific context** in the Protein assignments panel. **Edit sample conditions and experiments** opens a form for the spectrum active when editing began. Select existing sample conditions or choose **New sample conditions**; IDs are managed automatically. Record temperature in kelvin, pH (inclusive 0–14), solvent, isotope labeling and construct. Uncheck temperature or pH to leave it unknown. Describe modifications, ligands or special bonding in **Nonstandard chemistry**. Confirm **Reviewed: single major conformer** only after review. Choose the experiment type, each acquisition-axis role in F1/F2/F3 order, and record the metadata source. Editing a shared sample changes the conditions used by every linked spectrum; create a separate record for different conditions. Saving validates the draft, supports Undo/Redo and embeds the records in the project.

The draft retains its original spectrum and context baseline. If Undo/Redo or another operation changes the current context, saving is blocked. **Reload current context (discard draft)** replaces the draft with current records; **Discard context edits** closes it without saving. Unrelated document edits do not invalidate the baseline. Deletion of the draft spectrum also blocks saving, even if that spectrum had no saved experiment metadata. Reloading opens sample-only editing; **Keep sample edits (sample-only)** removes the deleted spectrum association while retaining the sample edits. Apply or cancel advanced JSON first. If the saved context also changed, its conflict must still be resolved. **Advanced JSON** is optional: apply or cancel its edits before saving; applying JSON only updates the draft and does not bypass validation or conflict protection.

Experiments reference a stable sample-condition ID. Reuse an ID only for identical conditions; use separate records for different conditions. Roles refer to acquisition F1/F2/F3, independently of display order and acquired nuclei. `observed_proton` and `indirect_proton` distinguish the two proton axes in NOESY. Unknown experiments/roles remain browsable and assignable, but block role-dependent structure operations. Known roles require matching acquired nuclei.

The initial structure scope is one standard-residue chain, one major conformer and supported dense 3D spectra, with manual assignments and external calculation. The scope check reports missing context or unsupported chemistry; it does not validate experiment connectivity, assignments or NOE measurements. No structure calculation or constraint generation is supplied by this step.

## Chemical-shift reference

In the Protein assignments panel, expand **Chemical-shift reference** and select **Edit reference**. Enter absolute F1/F2/F3 offsets in acquisition order (ppm), record the standard or comparison evidence, and explicitly confirm your review before saving. Corrected coordinates equal acquisition coordinates plus the offset; saving the same offset twice does not add it twice. Spectrum planes, peak coordinates and JSON exports use corrected ppm. Peak IDs and assignments remain stable. Undo/redo and project saving retain the reference and its source. Phase changes retain the correction.

The panel reports reference readiness against other spectra with experiment metadata. Both references require manual confirmation and the same sample-condition ID. Different conditions cannot be silently merged. This is a manual reference review, not an automatic peak alignment or certification of matching nuclei, axis roles or chemical shifts. Review those before combining observations. Reference changes may invalidate downstream scientific interpretations.

Confirmed single-atom observations with matching atom identities and nuclei are shown individually as left-minus-right corrected ppm differences. Ambiguous groups are excluded; no matches means not evaluated. No averaging, tolerance verdict or automatic correction is performed.

The reference form names its draft target. When you switch spectra, a warning explains that Save still edits that target. Reference coordinate changes, including undo/redo, clear affected Inspect/Delta pins and slice cursors because their stored readings are no longer valid.

## Chemical-shift list

Open **Chemical-shift list** in the Protein assignments panel after recording sample conditions for every assigned spectrum. Rows identify each residue by molecule, chain, residue code and sequence number, and group the same atom target and nucleus within one sample-condition ID. Each acquisition-axis observation retains its peak and candidate identity, corrected ppm, reference source and confirmation; partial assignments and OneOf/Shared groups remain intact. Groups are never expanded into independent atoms.

Compare all observations, enter a known uncertainty in ppm (otherwise leave it unknown), and add a review note. **Select** requires a confirmed assignment and reference; **Exclude** retains the original evidence. **Reset / save error** saves uncertainty and notes with a pending decision. Different values are never averaged, and multiple selections do not certify consistency. Editing sample conditions (including pH, temperature or solvent) under the same sample ID also invalidates decisions and unsaved review drafts. Missing or changed observation snapshots show Pending and require review again. Decisions support undo/redo and project save/reopen. This panel does not assess chemical correctness or experimental connectivity.
